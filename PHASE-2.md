# Phase 2 — Database & Core Domain Model

## Status
Implemented.

## Scope
This phase establishes the PostgreSQL persistence foundation for the eight core tables named in the assignment:

- users
- profiles
- doctors
- availability_slots
- consultations
- prescriptions
- payments
- audit_logs

The schema intentionally does not introduce unrelated product entities.

## Migration
Run from the project root:

```bash
npm run db:migrate
```

The migration runner creates/uses `schema_migrations` to track applied migration versions. This is infrastructure metadata, not an additional business-domain table.

## Database Design Notes

- UUID primary keys are generated by PostgreSQL through `pgcrypto`.
- Foreign keys enforce the relationships required by the domain model.
- `availability_slots` prevents duplicate doctor/time-window records.
- `consultations.availability_slot_id` is unique so one slot can back at most one consultation.
- `payments.consultation_id` is unique for a one-to-one payment record per consultation in this core model.
- `availability_slots` has a database check ensuring the end is after the start.
- Payment amounts cannot be negative.
- Audit metadata uses JSONB to retain structured event metadata without introducing extra domain tables.
- Initial indexes target the relationship and time/status access patterns needed by later workflows.

## Important Scope Boundary

The assignment specifies table names but does not specify a complete column-level schema, exact role values, lifecycle states, payment provider, or other product-specific details. The implemented fields are therefore the minimum persistence structure needed to support the stated workflows and later phases. Detailed business validation/state rules will be implemented in their respective phases.

## Phase 2 Verification

After PostgreSQL is available and `DATABASE_URL` is configured:

```bash
npm run db:migrate
npm run build
```

The expected migration output is:

```text
Applied migration: 001_core_domain
```

Running the migration again should not re-apply the migration.
